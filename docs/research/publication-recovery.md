# Saved-evidence publication and recovery

Reporting consumes retained evidence; it never runs fitting, encoding, acquisition,
outcome access or bootstrap inference. Inspection identity requires the same
resolved file and exact SHA256 under the reference's existing working-directory
meaning, plus its terminal G0 publication. A producer-authorized `blocked`
inspection remains verified historical evidence with its blockers displayed.
Target eligibility additionally requires completed, compatible inspection.
Different files with identical content do not authenticate each other.

The generic report renders into a temporary directory on the publication
filesystem. Its inventory is checked before replacement. Native packaging checks
the previous selector, receipt, terminal owner and scientific hashes before
rendering. CSV validation requires exact schemas and method/comparator identities,
saved finite values and coverage, complete-case metadata, and independently bound
actual-work rows. Reservations and actual starts are separate quantities;
unavailable counters remain unavailable.

Publication uses a small recoverable protocol, schema version 1:

1. `.publications/<role>-<uuid>/` retains all prospective files, byte-exact old
   projections and a checksummed manifest. These bundles are retained locally.
2. `.<role>.publication.json` durably records the prepared transaction before
   any live file changes. A POSIX lock excludes competing aggregate writers.
3. Live projections are replaced from retained members; the selector is last.
   This sequence is recoverable through the manifest, rather than being treated
   as an inherently atomic multi-file operation.
4. Native packaging calls `ledger.finish` with its exact receipt reference.
   Only a completed terminal G6 owner qualifies that selection as successful.
5. Recovery verifies all retained members first. An unfinished/failed owner
   restores the prior projections and selector; a completed exact owner finishes
   projecting its validated new bundle. Neither recovery branch reruns science,
   removes charged usage, or completes an interrupted owner. A corrupt manifest
   fails closed and retains both bundles for explicit investigation.

If ordinary reporting encounters interrupted native packaging, recover with the
original path arguments:

```sh
python scripts/render_results_first_study.py \
  --results /original/results --docs /original/docs --recover-only
```

This command needs the original ledger and compatible configuration, but makes
no new admission. It can restore evidence even when the abandoned attempt's
conservatively charged time prevents a new reporting admission. The interrupted
ledger record stays unfinished until the ledger's existing admission-time
reconciliation runs. Then use the documented reporting commands if a new report
is wanted. Deleted/stale committed native selectors and modified prior published
files require explicit investigation; they are never reconstructed by choosing
a filename or modification time.

The generic library selector explicitly attests only validated aggregate
publication, with no terminal CLI owner asserted. A native selector also binds
its receipt and exact successful accounting owner. Historical receipts and
scientific exports remain authoritative for their original source; source changes
do not authorize a new confirmation experiment. The new recovery tests use
synthetic fixtures, including subprocess exits on both sides of terminal
accounting. The private native campaign has not been regenerated by these tests.
